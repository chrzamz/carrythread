# Carrythread · 续迹

**接上工作脉络，把事情推进到结果。**

[English](README.md) · [宣传网站](https://chrzamz.github.io/carrythread/) · [版本发布](https://github.com/chrzamz/carrythread/releases) · [隐私说明](docs/PRIVACY.md#中文) · [参与贡献](CONTRIBUTING.md#中文)

Carrythread 是给跨多个 AI Agent、多个项目工作的人使用的本地桌面工作台。它读取已有对话记录，找回决定与未尽事项，并为你选择的工具准备继续工作所需的上下文。

一次回答完成，不一定代表交付完成。Carrythread 分开记录产出、测试、发布与验收，保留可检查的依据，也允许你纠正状态。

> **v0.1.0 正在进行发布验证。** 目前可按下方说明从源码运行。本地 macOS 源码端到端与已记录的核心检查已在对应检查点通过；最终本地检查已通过 130/130 测试、类型检查、构建、source E2E及本机加固生产包的renderer-CDP E2E，后者不使用Node inspector或主进程testhook；最新头跨平台构建仍待执行。真实模型 HTTP、安装器、原生目标与签名证据分别记录在[发布检查清单](docs/RELEASE-CHECKLIST.md)。只有出现在 [Releases](https://github.com/chrzamz/carrythread/releases) 中的文件才是实际发布物；不要把构建目标当成已发布或已签名安装包。

## 可以做什么

- **跨工具读取：** 本地 Codex、Claude Code、OpenCode、Pi、Finch，以及明确选择的 JSON / JSONL / Markdown 文件。
- **按事情回顾：** 从所选依据整理决定、当前阶段、未知项、完成条件与下一步。
- **保留原始依据：** 来源摘录、消息引用、日期和覆盖缺口可检查。
- **纠正工作记录：** 编辑、合并或拆分事项；后续回顾保留手动覆盖、暂停和取消状态。
- **带着上下文继续：** 预览已登记的交接材料，选择目标和工作目录，再使用实际可用的打开、恢复、CLI 或复制路径。随后读取新对话，把相符的后续工作接回原事项。
- **掌握数据边界：** 本地 SQLite、明确触发的 AI 请求、自备服务密钥或本地模型，以及不含模型密钥的工作区导出。

应用与宣传站包含**英语、简体中文、西班牙语、日语**。源文本保持原语言，AI 生成的回顾使用所选输出语言。

## 从源码运行

需要 **Node.js 24 或更新版本**、`package.json` 固定的 **pnpm 10.34.4**，以及能够运行 Electron 的桌面环境。

```sh
git clone https://github.com/chrzamz/carrythread.git
cd carrythread
pnpm install --frozen-lockfile
pnpm dev
```

若尚未安装 pnpm，请用你习惯的包管理方式安装 `packageManager` 指定版本。保留锁文件，不要顺手更换依赖版本。

```sh
pnpm check       # 类型检查、专项测试与生产构建
pnpm build       # 构建桌面应用
pnpm start       # 在本地预览构建结果
pnpm package     # 本地构建并打包，不发布
pnpm site:build  # 准备静态宣传网站
```

配置的打包目标是 macOS DMG / ZIP、Windows NSIS / portable、Linux AppImage / DEB。配置目标不代表已经构建或实测；实际结果见[平台验证表](docs/RELEASE-CHECKLIST.md#platform-evidence)。本地打包不会自动完成签名、公证或发布。

## 安装实际发布的版本

项目仍为 pre-release。只有 [Releases](https://github.com/chrzamz/carrythread/releases) 中实际存在的文件才适用以下步骤，先核对架构、SHA-256、验证说明与签名状态。

- **macOS：** 当前包声明最低 macOS 13.0；本机及 CI macOS 15 的检查不代表遍历了所有系统版本。打开下载的 DMG，将 Carrythread 拖入“应用程序”。未签名/未公证版本首次打开可能被系统阻止；核对来源和校验值后，可以查看“系统设置 → 隐私与安全性”中针对该应用的“仍要打开”。不需要、也不建议全局关闭 Gatekeeper。
- **Windows：** 下载对应 NSIS setup 程序并按安装向导操作。未签名版本可能触发发布者或 SmartScreen 提示，不具有已验证发布者签名；决定继续前先核对官方发布页与校验值。portable 包装程序的验收另列。
- **Linux：** 在兼容的 Debian/Ubuntu 系统中，通过软件包安装器，或将实际下载文件名代入 `sudo apt install ./downloaded-package.deb` 安装 DEB。AppImage 与正常沙箱启动有独立验证状态；CI 合成测试使用的 `--no-sandbox` 不是安装指引。

## 第一次回顾

1. 打开**记录来源**，检测常见本地历史位置，或明确选择目录/文件。只启用你打算导入的来源。
2. 刷新来源并检查覆盖报告。部分覆盖、无法访问、格式不支持和确实为空是不同状态。
3. 打开 **AI 连接**，选预设或自定义地址，填写模型和所需密钥，再运行合成内容连接测试。
4. 选择 **AI 回顾**，预览所选范围、检查勾选对话与目标服务后启动。所选消息、可用会话元数据及关联的既有事项上下文用于归并，预览会显示相关事项。
5. 检查结果：建议仍可保留为候选，纠正缺少依据的结论，确认实际交付前先看证据。
6. 准备交接，确认本次指令、目标和工作目录，查看材料后再按界面显示的能力打开或复制。

一次回顾最多分八批，每批依据最多 120 条消息、60,000 字符。超过边界会在任何网络请求前拒绝，缩小范围后再运行。

刷新来源只读取本地文件，不会自动运行 AI 回顾。自动刷新默认关闭；开启后也只在应用运行时刷新已启用来源。

## 来源支持与限制

| 来源 | 已实现的读取方式 | 当前边界 |
|---|---|---|
| Codex | 本地 JSONL 对话/事件记录，去除镜像重复 | 仅本地记录；未知格式或不支持文件会报告。不宣称覆盖全部云端或压缩历史格式。 |
| Claude Code | 项目 JSONL 可见正文和支持的用户问答结果 | 不连接 Claude 网页账号；不把推理或系统记录当作用户工作。 |
| OpenCode | 旧版 JSON、v1 SQLite、支持的 CLI 导出 JSON | 暂不解析新版 `session_message` 表，检测到内容时报告部分覆盖。 |
| Pi | 已保存的 JSONL v1–v3，保留树形关系 | 已覆盖合成格式样例；更广泛的实际版本兼容性需逐次发布验证。 |
| Finch | 原生 Pi 格式日志，runtime-v1 快照作为回退 | 原生日志优先；快照可能缺少事件时间，缺口会保留。 |
| 通用文件 | 明确选择的 JSON、JSONL、Markdown | 导入文档不证明文中事件发生在导入时间。 |

扫描器只处理所选来源，拒绝文件系统根目录和整个用户目录，跳过符号链接及已知凭证/配置路径，报告解析和大小限制。不会改写原始历史或数据库。移除来源或缩小扫描时间不会自动抹去已索引记录；需要清空时使用本地数据控制。

## AI 服务：自备凭证

已实现 **OpenAI-compatible chat completions**、**Anthropic Messages** 和 **Ollama** 三种协议。预设包含 OpenAI、Anthropic、Google Gemini（OpenAI 兼容）、OpenRouter、xAI / Grok、DeepSeek、Qwen / 阿里云百炼、GLM / 智谱、Moonshot / Kimi、Doubao / 火山方舟、SiliconFlow、Ollama 与自定义地址。预设只是配置便利，不代表背书，也不保证每个服务商的所有模型均兼容。

默认托管预设使用**普通 API 地址**。Carrythread 不通过 ChatGPT、Claude 或厂商 Coding Plan 订阅登录，不复用其订阅，也不会自动切到套餐专用地址。请自行选择账号允许使用的地址与凭证；模型用量和费用由相应服务商处理。

填写账号实际可用的模型名。模型列表发现是可选项，无法取得列表不代表手动填写的模型不可用。外部地址要求 HTTPS，仅明确的 localhost 地址允许 HTTP；请求不会携带密钥跟随重定向。修改连接地址或协议会清除原密钥，请有意识地重新为新地址填写密钥。xAI 预设使用 Chat Completions 兼容入口，不代表支持仅 Responses 协议提供的功能。

连接测试发送很小的合成提示词，不含导入对话，但仍可能消耗模型额度。真实回顾质量、模型可用性与实际服务测试，不能由协议单元测试代替。

## 交接表示一种具体动作

能够读取历史，不保证原应用仍能打开相应会话。Carrythread 会检测目标，并准备受限、已脱敏的 Markdown 材料，包含当前指令、决定、状态、未知项、所选摘录及来源指针。

| 目标路径 | 当前实现的行为 | 不代表什么 |
|---|---|---|
| macOS Codex 桌面端 | 带提示词的新聊天链接；原线程链接并复制上下文提示 | 打开或预填不等于已发送，更不等于已读取。 |
| Codex、Claude Code、OpenCode、Pi CLI | 在终端启动检测到的 CLI，传入新建/恢复参数及交接提示 | 提示词参数可能直接开始执行。需核验原生 CLI 版本行为，启动不是回执。 |
| macOS Finch 桌面端 | 新聊天链接；原聊天链接并复制上下文 | 新建链接可能开始执行，原聊天可能需要手动粘贴。 |
| 手动 / 其他工具 | 复制交接提示并导出 Markdown | 由你决定如何附加或粘贴材料。 |

预览后才明确启动。首次在某个目录发起 Agent 任务时，需通过系统文件夹选择器确认；后续会记住已确认目录。导入记录的 `cwd` 只是位置线索，不是该目录的执行许可。历史指令不会自动变成本次授权；事项在交接准备后发生变化时，需要重新生成。目标、会话或工作目录不可用时，可用手动导出，不应假定材料已送达。

可携带材料包含来源指针，不会复制全部项目文件。换电脑后，应让导出的文件与必要项目文件可访问，并重新核对工作目录。

### 本地记录如何接到新会话

链路是：**本地记录 → 已整理事项 → 已登记上下文包 → 选定 Agent → 重新读取后续记录**。请完整复制继续提示，其首行引用标识本地 Carrythread 工作区已登记的交接。

新用户消息导入后，Carrythread 会用交接 ID、事项 ID、修订版本及目标核对本地登记。有效引用可以在换 Agent、标题或目录后，将原事项的最新决定带入本次所选回顾；不会倒退到旧修订，也不会因此发送未勾选原对话的消息。同一个会话里的新话题不会自动视为同一任务。

使用交接提示时保留引用首行。缺失、改写、未知或仅在助手引用中出现的标记不能建立关联。标记只是连续性依据，不是新授权、加密回执或目标已读文件的证明；仍需检查归并结果并按需纠正。

来源提供时，会话上下文包含 Agent、标题、目录名项目提示与规范化工作目录的哈希。这是可选的来源元数据，不是独立设置开关，也不是全局项目身份。完整工作目录不作为该专用元数据字段发送，但正文和交接文件仍可能含路径。

工作区导出不包含本地交接登记表。上下文文件仍能在另一台电脑阅读，但仅导入它或可携带工作区，不会在新设备重建受信任的标记关联。

## 隐私与本地数据

原始历史只读。Carrythread 在自己的应用数据目录保存索引、事项、纠正、设置和交接材料。工作区数据库**并非整体加密**；模型密钥可用时采用OS保护的加密存储；macOS打包版通过匿名管道调用同签名短命helper，helper没有窗口、Store或网络，presence展示不解密，实际使用才取密钥。超时/不可用时有界地退回当前会话，不落明文。

AI 回顾由你明确触发，所选依据、可用会话元数据及关联事项上下文会发给指定服务商。已登记交接可把所选新会话关联到既有事项，而不发送未选中的旧对话。本地 Ollama 可将推理保留在本机。脱敏不是完整匿名化，姓名、项目文本、来源路径等敏感信息仍可能保留在记录或导出中。

**“导出工作区”导出的是整个已索引工作区**，包含会话、依据、事项及变更历史，不包含服务设置/密钥和已准备交接记录。请妥善保存导出文件。清除 Carrythread 本地数据不会删除 Agent 原历史、之前导出的文件，或已交给其他工具/服务商的副本。

详见[隐私说明](docs/PRIVACY.md#中文)与[安全报告](SECURITY.md#中文)。
